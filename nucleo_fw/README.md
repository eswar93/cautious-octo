# nucleo_fw — base station (NUCLEO-F767ZI)

`app/` and `../core/` (modern C++20, no exceptions/RTTI/heap) are the only hand-written sources. Everything else (HAL, lwIP, FreeRTOS,
startup, linker script) is generated by STM32CubeMX, so regenerating never clobbers your code.

## Where things go
```
telemetry-predictor/
  core/             shared portable code
  nucleo_fw/
    nucleo_fw.ioc   your CubeMX config (commit it)
    CMakeLists.txt  generated; add the lines from step 4 in its USER CODE sections
    Core/ Drivers/ Middlewares/ LWIP/   generated
    app/            hand-written
```
In CubeMX *Project Manager*: Project Name `nucleo_fw`, Project Location = the **repo root**
(CubeMX appends the project name itself), Toolchain/IDE = **CMake**.

## 1. Tools (Windows 11)
STM32CubeMX, VS Code + the **STM32 VS Code Extension** (installs Arm toolchain, CMake, OpenOCD,
CubeProgrammer). ST-LINK drivers come with CubeMX.

## 2. CubeMX settings (order matters)
1. Start from the NUCLEO-F767ZI board preset.
2. **FREERTOS**: Interface = **`CMSIS_V1`**.
   With `CMSIS_V2` the LWIP `NO_SYS` dropdown only offers "OS Not Used" (observed on this setup),
   so lwIP cannot be put in RTOS mode. FreeRTOS underneath is the same; this project's code calls
   native FreeRTOS functions.
   - *Config parameters*: **ENABLE_FPU = Enabled** (the F767 has an FPU and the code uses floats);
     `TOTAL_HEAP_SIZE` >= 32 KB.
   - *Tasks and Queues*: raise the default task's stack size to **>= 512 words** (it runs `MX_LWIP_Init()`).
3. **SYS** (System Core): *Timebase Source* = a spare basic timer (**TIM6**, or TIM7).
   This clears CubeMX's "use a timebase other than SysTick" warning; `HAL_GetTick()` keeps working.
4. **ETH** (Connectivity): RMII, pins as in the board preset.
5. **LWIP**: untick/tick *Enabled* once after FreeRTOS is set so it re-reads the OS. Then:
   - *Key Options*: `NO_SYS` = with OS; `LWIP_NETCONN` and `LWIP_SOCKET` on.
   - *General Settings*: `LWIP_DHCP` = Enabled.
   - *Platform Settings*: `Driver_PHY` = **LAN8742** (the PHY on this board).
6. Generate. Verify `LWIP/Target/lwipopts.h` contains `WITH_RTOS 1` (the `NO_SYS`/`LWIP_SOCKET`
   lines disappear because they now match lwIP's defaults, which is correct).

## 3. lwIP receive-timeout option (required)
In `LWIP/Target/lwipopts.h`, inside the user section (kept on regeneration):
```c
/* USER CODE BEGIN 1 */
#define LWIP_SO_RCVTIMEO 1
/* USER CODE END 1 */
```
Without this, `recvfrom()` blocks forever and `LINK LOST` can never be detected.
(`udp_task.cpppp` has a compile-time `#error` if it is missing.)

## 4. Add our sources — top-level `CMakeLists.txt`
The generated project is C + ASM only; our code is C++20, so enable C++ as well. Put this in the
generated file's USER CODE sections (names vary slightly by CubeMX version; if a section is
missing, add the lines at the end and check they survive one regeneration):
```cmake
enable_language(CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE
    ../core app ../third_party/mavlink/c_library_v2/common ../third_party/mavlink/c_library_v2)
target_sources(${CMAKE_PROJECT_NAME} PRIVATE app/base_station.cpp app/udp_task.cpppp)
target_compile_options(${CMAKE_PROJECT_NAME} PRIVATE
    $<$<COMPILE_LANGUAGE:CXX>:-fno-exceptions -fno-rtti -fno-threadsafe-statics>)
target_link_libraries(${CMAKE_PROJECT_NAME} m)
```
Notes
- `core/` is header-only, so there are no core `.cpp` files to list.
- ST's `cmake/gcc-arm-none-eabi.cmake` normally already sets `CMAKE_CXX_COMPILER` to
  `arm-none-eabi-g++` and adds the C++ flags above; the explicit options are harmless duplicates.
  If CMake says it can't find a C++ compiler, that file is where to look.
- `std::span` and designated initializers need C++20 and a GNU Arm toolchain >= 10 (the STM32 VS Code
  extension installs a newer one).
- The alert text uses integer percentages (`p=87%`), so no `-u _printf_float` linker option is needed.
- `core/model_weights.hpp` is generated by `ml/train.py` (already in the repo). MAVLink headers
  come from `tools\fetch_mavlink.ps1`. If the MAVLink headers produce warnings under C++, silence
  them for that include only, not project-wide.

## 5. Start the task — `Core/Src/freertos.c`
Inside USER CODE sections:
```c
/* USER CODE BEGIN Includes */
void udp_task(void *arg);
/* USER CODE END Includes */
...
/* in MX_FREERTOS_Init(), USER CODE BEGIN RTOS_THREADS */
xTaskCreate(udp_task, "udp", 2048, NULL, tskIDLE_PRIORITY + 3, NULL);   /* stack in WORDS */
```
(Under `CMSIS_V1`, `MX_LWIP_Init()` is called from the default task's body; `udp_task` can start
before DHCP finishes because binding to INADDR_ANY doesn't need an address.)

## 6. Debugging
- The Nucleo gets its IP by DHCP: read it from your router's client list, then set it on the ESP32
  (`idf.py menuconfig` -> Remote node -> Base station IP).
- Wireshark on the PC, filter `udp.port == 14550` (MAVLink dissector is built in).
- ST-LINK virtual COM port (USART3, 115200) is handy for `printf` logging.
- If nothing arrives: check the link LEDs on the Ethernet jack, ping the Nucleo from the PC, then
  check the stack-overflow hook (`configCHECK_FOR_STACK_OVERFLOW`) before suspecting lwIP.
